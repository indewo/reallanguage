## B. 项目结构与运行方式

### 技术栈

- 用户客户端：原生 Android、Kotlin、Jetpack Compose。

- 本机数据库：PGlite，目录 `.local-data/reallanguage-db`。
- 正式数据库：PostgreSQL + Kysely。
- 异步单元：独立 Worker 与 Scheduler，用于支付状态和退款对账。
- 管理后台：React 19 + Vite 8；当前只有骨架。

## F. 本轮已修复问题

### 1. OpenAI 请求在本机返回 500

- 根因：系统 DNS 将 `api.openai.com` 解析到错误地址，而 Node 默认没有读取已有 HTTP(S) 代理环境变量。
- 修改：`apps/api/package.json` 的本机启动命令显式启用 Node 环境代理。
- 回归：真实英文候选生成从 500 恢复为成功，完整 API 链路连续两次通过。

### 2. 生产构建产物无法启动

- 根因：工作区包 `exports` 指向 `.ts` 源码；编译后的 API、Worker、Scheduler 由 Node 启动时尝试从源码目录加载不存在的 `.js` 文件。
- 修改：database、backend-modules、contracts、observability、test-support 使用条件导出；开发/类型检查仍读源码，生产 Node 读取 `dist/*.js`。本机 API 启动命令增加 `development` 条件。
- 回归：三个生产进程均能越过模块加载阶段，并正确停在首个缺失的 `DATABASE_URL`；说明构建入口已修复，剩余是配置缺失而非包解析错误。

### 3. 密码重置仍要求 15 位

- 根因：Android `PasswordResetViewModel` 遗留最小长度 15，与 v1.26 的 4—64 位规则、后端密码策略和界面错误文案不一致。
- 修改：重置密码最小长度改为 4；对应测试的无效输入改为 3 位。
- 回归：481 个 Android JVM 测试和 ViewModel 覆盖率门禁通过。

### 4. 密码重置邮件与 App 回接缺失

- 根因：本机邮件泵只消费注册验证事件，Android 未声明或处理密码重置深链。
- 修改：增加密码重置 outbox 派发、加密字段解密、专用邮件、`reallanguage://password-reset/verify` 深链、进程重建恢复和安全本机邮件捕获模式。
- 回归：邮件生成、验证、重置、旧密码失效、新密码登录全部通过；模拟器实际打开深链并显示服务端验证结果。

### 5. Admin CORS 预检 404

- 根因：HTTP App 未配置任何允许来源。
- 修改：本机仅允许两个明确的 5173 来源；生产环境增加 HTTPS-only 来源列表配置。
- 回归：真实预检返回 204，方法与请求头均为受限列表。

### 6. 本机 AI 任务使用固定结果或静默兜底

- 根因：本机供应商只对少数任务调用 OpenAI，其余章节、目标、讲解、口语评分、练习和场景任务返回固定内容；英文和录音在模型无结果时还会伪造可用正文。
- 修改：所有生成、讲解、反馈、评分、场景与编辑复核任务改为按各自合同调用真实模型；音频反馈先使用真实转写作为证据；模型空结果统一 fail-closed；删除英文和录音伪造兜底。
- 回归：30 项本机 AI 供应商测试通过；章节、英文、目标、讲解、反馈、练习、场景与编辑复核的逐类真实 OpenAI 调用均返回有效结构；完整用户 E2E 通过；TypeScript 735/735、Android JVM 和模拟器 68/68 通过。

### 7. 模拟器并发测试导致包管理器异常

- 根因：两次 instrumentation 测试发生重叠，先启动的测试在后启动测试执行期间卸载 APK，造成首项进程崩溃和 `DELETE_FAILED_INTERNAL_ERROR`。
- 修改：确认无残留 Gradle/instrumentation 进程后重启模拟器，恢复包管理器，并先单项复现再串行执行全量测试。
- 回归：原失败首项单独通过，随后 68/68 全量模拟器测试通过，0 失败、0 跳过。

### 8. OpenAI 安全与拆句调用被固定结果掩盖

- 根因：安全固定 PASS、拆句使用标点算法；同时原始 Responses HTTP 结果被错误地按 SDK `output_text` 字段读取。
- 修改：安全与拆句改为真实 OpenAI 结果，修正 `output[].content[].text` 解析，删除这两项假成功；模型或输出无效时明确失败。
- 回归：真实安全、拆句和完整产品链路通过。
