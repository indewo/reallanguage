# RealLanguage 测试计划

> 文档版本：v1.0  
> 日期：2026-08-31  
> 对应统一产品基线：v1.26  
> 状态：已确认，可作为开发、合并与发布测试基线  
> 确认日期：2026-08-31  
> 适用范围：RealLanguage 第一版 Android 客户端、Backend API、Worker、Scheduler、Admin 及其外部适配器

## 1. 目的

本文把已经确认的产品规则、架构质量目标和设计验收矩阵转化为开发时可执行的测试范围、设备矩阵、覆盖率门槛、发布阻断条件和测试证据。

本文不重新定义产品规则。发生冲突时按 `CONTEXT_SOURCES.md` 的优先级处理；体验过程中用于快速走流程的“下一步”“假设完成”“跳过场景”“跳过环节”等指令，不得转化为正式测试预期。

本文重点回答：

- 每个功能在编码前、合并前和发布前分别要通过什么测试；
- 哪些失败必须阻止合并或发布；
- Android 横屏、字号、系统环境和真实设备如何覆盖；
- 本机学习资料与云端账号／计费数据的边界如何验证；
- AI、语音、支付、审核、并发、恢复和突发流量如何验证；
- 测试结果如何定位到需求、接口、代码和故障。

## 2. 测试原则

### 2.1 测试驱动开发

每个可独立交付的纵向功能切片必须按以下顺序完成：

1. 确认产品规则、验收条件和所属业务模块；
2. 定义公开接口、DTO、错误码和状态变化；
3. 先编写能够失败的测试；
4. 编写使测试通过的最小实现；
5. 在测试保护下重构；
6. 运行受影响模块、合同和关键链路回归；
7. 全部通过后再进入下一切片。

修复缺陷时必须先增加能够稳定复现问题的失败测试。不得先完成多个页面或接口，最后集中补测试。

### 2.2 风险优先

测试数量不平均分配。以下路径按最高风险处理：

- 余额预留、供应商真实调用、结算、释放、退款和账本；
- 内容审核、整章拦截、AI 脱敏版和人工复核；
- 章节固定、普通学习归档、放弃章节和统一回顾整章提交；
- 本机账号隔离、卸载／清除数据后的不可恢复边界；
- 原始录音、后台录制、两分钟截止、转写失败和隐私；
- 并发、重复请求、任务重投、支付回调重放和供应商切换；
- OpenAPI、模块公开合同、数据库迁移和旧客户端兼容。

覆盖率只能帮助发现测试缺口，不能代替关键业务分支、不变量、并发副作用和端到端结果测试。

### 2.3 可重复与可定位

- 单元测试不访问网络、真实时间、系统随机数或共享数据库；
- 时间、ID、汇率／价格、供应商响应和任务调度通过可控 Port 注入；
- 失败结果必须显示测试用例、业务模块、合同版本、请求／operation ID 和必要诊断信息；
- 日志和测试报告不得出现录音、原文、固定中英文、Prompt、密钥或完整个人信息；
- 同一提交在相同环境和输入下应得到相同测试结果。

## 3. 测试层级与职责

| 层级 | 主要对象 | 外部资源 | 每次提交 |
|---|---|---|---|
| Domain 单元测试 | 实体、值对象、领域服务、状态机、不变量 | 无 | 必跑 |
| Application 单元测试 | Use Case、权限、编排、事务意图、幂等入口、错误映射 | Fake Port | 必跑 |
| Adapter 集成测试 | Room、PostgreSQL、Redis、队列、对象存储、支付／AI Adapter | 隔离测试实例或可编程 Stub | 受影响范围必跑 |
| 模块合同测试 | Public Command／Query／Event | 受控环境 | 必跑 |
| API 合同测试 | `/api/v1`、OpenAPI、认证、DTO、错误、兼容性 | 测试服务 | 必跑 |
| Android 测试 | ViewModel、Repository、导航、状态恢复、Compose、录音服务 | Fake API＋模拟器／设备 | 受影响范围必跑 |
| AI 回归测试 | Schema、业务校验、质量样例、供应商切换 | Fake 为主、受限真实调用 | Fake 必跑；真实调用按计划 |
| 端到端测试 | 关键用户闭环 | Staging／支付沙箱 | 合并冒烟＋发布全量 |
| 非功能测试 | 并发、容量、故障、安全、恢复、可观测性 | 隔离环境 | 定时＋发布前 |

测试应优先落在拥有规则的最低层。页面测试不重复验证全部领域组合；端到端测试只保留关键闭环和跨模块风险。

## 4. 需求与测试追踪

### 4.1 标识规则

每个正式测试用例至少关联一种稳定标识：

- 产品规则或验收条目；
- `SCREEN_MAP.md`／`SCREEN_SPEC.md` 页面编号；
- OpenAPI operation ID；
- 模块公开 Command／Query／Event；
- 数据迁移版本；
- 缺陷编号。

建议测试 ID 使用：

```text
RL-{MODULE}-{LEVEL}-{NUMBER}
```

示例：`RL-LEARNING-DOMAIN-001`、`RL-BILLING-CONCURRENCY-004`、`RL-ANDROID-UI-012`。

### 4.2 完整性检查

CI 自动检查：

- 新公开接口、错误码和状态枚举存在相应测试；
- 新数据库迁移存在升级测试；
- 高风险规则存在正常、失败、重复和并发场景；
- 已修复缺陷保留回归测试；
- 被删除或改名的合同没有遗留失效测试。

## 5. 测试环境与数据隔离

### 5.1 环境

| 环境 | 用途 | 禁止事项 |
|---|---|---|
| 本机 | 单元、静态检查、Fake 合同、局部 Android 测试 | 生产账号、生产密钥、真实支付 |
| CI 隔离环境 | 全量自动测试、数据库／队列集成、模拟器 UI | 共享可变账号、无预算真实模型 |
| Staging | 端到端、容量、故障注入、支付沙箱、受控供应商联调 | 真实用户资料、生产支付商户 |
| 生产只读验证 | 发布后健康检查和指标观察 | 写入测试内容、模拟扣费或破坏性故障 |

测试和生产必须使用不同的数据库、对象存储、队列前缀、支付商户、供应商密钥和推送配置。

### 5.2 隔离规则

- 每个并行测试使用唯一用户 ID、账号隔离标识、幂等键、订单号、operation ID、对象路径和队列名；
- PostgreSQL 测试使用独立数据库、独立 Schema 或能够完全回滚的隔离事务；
- Room 测试为每个用例创建独立数据库和 App 私有目录；
- 测试不得依赖执行顺序或共享余额、学习状态、审核任务和本机录音；
- 测试结束必须清理临时对象和消息，清理失败本身视为测试失败；
- 真实供应商测试只使用专用账号、脱敏样例、调用次数上限和人民币预算上限。

## 6. 代码覆盖率门槛

首版采用以下建议门槛：

| 范围 | 行覆盖率 | 分支覆盖率 | 额外要求 |
|---|---:|---:|---|
| Domain／Application | ≥ 90% | ≥ 85% | 状态机、不变量和明确错误分支必须全部覆盖 |
| 计费、审核、删除、归档、回顾提交 | ≥ 95% | ≥ 90% | 幂等、并发和副作用次数必须有专门测试 |
| Adapter／Repository | ≥ 80% | ≥ 75% | 约束、事务、序列化和失败恢复必须覆盖 |
| Android ViewModel／Use Case | ≥ 85% | ≥ 80% | 导航、恢复和所有用户可见状态必须覆盖 |
| 全仓可统计业务代码 | ≥ 80% | ≥ 75% | 生成代码、声明式资源和第三方代码排除 |

新变更不得降低其受影响模块的覆盖率。即使达到百分比，只要关键分支未测仍不得合并。

## 7. Android 设备与窗口矩阵

### 7.1 自动化基础矩阵

CI 至少覆盖以下 Android API 等级：

| API | 目的 |
|---:|---|
| 26 | 最低支持版本 |
| 30 | 较旧系统行为与权限兼容 |
| 33 | 通知权限和后台行为变化 |
| 35 | 近年系统、边到边和 Insets |
| 36 | 当前 target／compile 基线 |

每次提交运行 API 26 和 API 36 的核心测试；API 30、33、35 在每日全量回归和发布候选中运行。

### 7.2 真实设备矩阵

每个发布候选至少在以下四类真实设备上完成核心链路：

1. API 26—28、内存较小的旧 Android 手机；
2. 近两年 Samsung 手机；
3. 近两年 Xiaomi／Redmi 手机；
4. 近两年 OPPO、vivo 或 Honor 手机至少一台。

设备型号可以随市场变化替换，但不得减少旧系统、主流中国厂商和当前系统三类覆盖。录音、后台录制、权限、系统返回、通知、进程终止和本机文件测试必须包含真实设备。

### 7.3 横屏与字号

所有核心页面和通用组件至少覆盖以下可用窗口，不含系统 Insets：

- `640 × 360dp`；
- `800 × 450dp`；
- `960 × 540dp`；
- `1280 × 720dp`。

每个窗口覆盖 `100%`、`130%`、`160%`、`200%` 系统字体比例。全组合用于自动截图和布局检查；关键交互用例至少覆盖紧凑、标准、宽屏各一组以及 `200%` 字体。

必须另外验证：

- 状态栏、导航栏、挖孔、圆角和边到边 Insets；
- IME 打开／关闭、外接键盘、分屏、窗口改变和系统返回；
- 前后台切换、进程终止后恢复、低内存重建；
- 触控、麦克风、手指抄写和系统通知权限；
- 屏幕阅读、焦点顺序、对比度、至少 `48 × 48dp` 触控目标、非颜色表达和减少动态效果；
- `200%` 字体下核心操作仍可完成，文字、按钮和错误不得被裁切或遮挡；
- 中英长文本、极端长单词、空状态、加载、禁用和错误状态。

## 8. 核心功能测试矩阵

### 8.1 账号、首次设置与首页

- 14 岁以上门槛、邮箱注册／登录、会话持久化和失去账号信息后的重新登录；
- 首次设置中途关闭后，下次进入重新填写；完成后按已确认设置进入首页；
- 退出到后台时的退出提示和“下次不再提示”；
- 首页三个内容入口、统一回顾到期和未完成学习按真实状态显示；
- 首页不显示人民币余额；费用页显示余额、来源、消费和充值；
- 不把声线选择或未经确认的跳过按钮加入页面；
- 每自然日最多一个提醒，内容可组合到期回顾、未完成学习和愿景激励。

### 8.2 三个内容入口

分别覆盖日记／文字、AI 场景和快速录音：

- 未提交输入、确认、返回、放弃和重复提交；
- AI 场景追问、唯一确定结果、用户学习／不学习选择；
- AI 场景三入口差异：推荐点击后的请求只含推荐标题、不含旧正文／旧对话／推荐理由／来源引用；直接描述将用户输入作为首份事实；公开模板不伪造预先人工描述；
- 推荐最多 4 个并按关联固定内容完成时间从新到旧稳定排序；新内容加入后顺序按同一规则迭代；
- 同一账号重复打开场景首页直接读取本机最多 4 条推荐且不新增网络/AI 请求；固定内容指纹变化只刷新一次，失败保留旧列表；空结果不反复请求，不同账号缓存互不可见，注销后对应缓存清空；
- 追问必须至少完成 3 问，从第 3 个回答开始逐答重判；当 1 个、最多 2 个具体时刻已足够形成至少 3 句有效内容时，在第 10 问前立即生成，不因所选时刻之外的旁支信息未知而继续追问；问题 ID 或规范化文案重复时拒绝；第 10 问后若回答已有多条可组成具体场景的有效事实，即使模型误报信息不足也必须恢复为生成，只有重复、含糊或无有效事实时才返回`INSUFFICIENT_INFORMATION`，客户端显示`信息缺失，无法生成内容`、保留回答且不调用草稿生成；
- 对话和文章草稿均不少于 3 个真实、连贯且不重复的单位；1—2 句、循环改写、无关回答和第 11 问均为反例；
- 录音点击后立即开始、无震动、弱化但可被用户看见的录音状态；
- 后台继续录制、最长两分钟自动停止、最后不完整语义单位丢弃；
- 转写失败页只有重试和返回，不存在删除按钮，返回不删除本机录音；
- 原始录音只在本机长期保存，用户只能在规定入口主动删除。

### 8.3 内容安全与固定

- 每份新的学习内容在进入学习前独立审核；
- 发现问题时整章不可学习，并提供 AI 脱敏版本或用户手动提交人工复核；
- AI 生成的脱敏版经用户确认后无需再次审核；
- 用户也可以确定新的内容重新进入独立审核；
- 审核未通过、处理中、通过、驳回、超时和重复提交状态准确；
- 固定内容确认后，在后续学习中原文、英文和验证目标不可修改；
- 用户返回固定模板确认之前，可以修改或更换模板；
- 固定操作重复提交只产生一个正式本机章节。

### 8.4 普通学习

- 重点句、唯一词义、唯一句式结构和生词结果与固定内容一致；
- 重点句候选来自全文最小语义单位：覆盖“情绪→原因→转折→结果→补充动作”的逗号长段不得整体显示为一句；枚举和不可拆的条件结构不得仅按标点误拆；
- 每个句式允许用户选择学习或不学习；允许全部取消；
- 学习流程、讲解轮次、朗读、听写、验证和状态更新符合规格；
- 手指抄写固定确认两次，每次点击`我已写完`，第二次后可不限次`再抄一遍`；
- 手写不识别、不比对、不纠错，也不保存笔迹；
- 键盘输入按固定英文确定性比对拼写、漏词、增词、换词和词序；
- 普通学习每个有效步骤在本机保存，可从当前步骤恢复；
- 用户确认放弃未完成章节时，删除本章固定内容、临时进度和本章尚未归档的学习贡献；
- 放弃不影响本章开始前已有的知识项、已完成章节或其他来源贡献；
- 完成章节以一个本机事务归档知识状态、未完成能力和普通学习日，重复提交不得重复累计。

### 8.5 词汇本与句式本

- 三个内容入口共享同一词汇本、句式本和知识状态；
- 同词不同义和屈折变化按语义身份规则处理；知识身份无法确定时先分开，其他 AI 内容在用户仍无法确认时才可按合同给出带`推测`标记的最可能结果；
- 代表场景和恰好三个例句的稳定性；既有知识再次出现只增加正确计数，不替换历史代表内容；
- 词汇本不提供未经确认的逐项删除；
- 用户完成学习后可以把内容移出句式本，固定句和章节归档不受影响；
- 跨账号、退出登录和重新登录时，本机知识本严格隔离。

### 8.6 统一回顾

- 完成三个不同的实际普通学习日后形成回顾周期；回顾日不计普通学习日；
- 每个回顾自然日最多完整处理三个重点句；
- 多章节回顾按原章节身份组织，只复习当前未完成能力；
- 完整完成第一章后保存第一章；第二章中途退出时仅清除第二章临时进度；
- 再次进入从第二章章首开始，第一章完成结果保留；
- 当前回顾章没有普通学习式的逐步保存；
- 余额不足后选择不充值时，按退出所在状态的既有规则决定是否保留，不能统一误用普通学习或回顾规则。

### 8.7 费用、充值与消息

- 用户自选充值金额，候选金额下的愿景文案不被当成固定套餐或 Token 数量承诺；
- 用户资产和扣费均按人民币展示与结算；
- 模型来源显示实际供应商／模型，不把 OpenAI 或任何供应商写死；
- 所有产生真实 Token 消耗的行为均按已确认倍率收费；
- 不在每次 AI 操作前弹出付费确认，也不在首页显示余额；
- 余额不足时不调用供应商，进入充值路径；
- 支付处理中、成功、失败、退款、回调延迟、重复回调、金额不符和签名错误状态准确；
- 人工复核结果、系统消息和通知不改变学习或账本状态。

## 9. 数据边界与恢复测试

### 9.1 本机权威数据

以下内容必须验证只在当前 Android 设备长期保存，并按账号加密隔离：

- 来源、固定章节和已确认生成结果；
- 普通学习进度、章节归档和知识状态；
- 词汇本、句式本、统一回顾周期／队列／章节；
- 原始录音和本机索引。

服务器数据库、对象存储、日志、Trace、备份和分析数据中不得出现这些内容的长期镜像。

### 9.2 云端数据

验证服务器只长期保存已确认范围内的账号、登录、资料、设置、人民币余额、订单、账本、必要审核／风控／供应商调用记录、消息和最后学习最小状态。

最后学习状态只能含不透明本地 ID、环节、完成标记和更新时间；不得包含正文，也不能从服务器重建学习资料。

### 9.3 恢复与丢失边界

必须覆盖：

- App 前后台切换、进程终止和设备重启后，从本机恢复普通学习当前步骤；
- 已交付并保存在本机的 AI／语音结果，恢复页面时不重复调用、不重复扣费；
- 统一回顾未完成章退出后按章首恢复，而不是恢复章内步骤；
- 断网时不能进入或查看本机学习资料，也不能正式学习；恢复网络并重新鉴权后才可从本机恢复；
- 卸载、清除 App 数据或更换设备后，服务器无法恢复学习资料；
- 退出账号后隐藏并隔离原账号资料；同一账号在原设备重新登录后可恢复本机资料；
- 临时 AI／语音正文交付后按配置期限从服务端清理，并保留不含正文的必要审计结果。

## 10. AI、语音与供应商合同测试

### 10.1 默认策略

自动测试默认使用可编程 Fake，能够稳定模拟：

- 成功、业务拒绝、Schema 错误和语义不合格；
- 超时、限流、连接中断、重复、乱序和迟到结果；
- 供应商切换、部分用量回报、缺少用量和未知模型名；
- 内容安全拦截、脱敏生成、人工复核提交和结果返回；
- 转写末尾完整／不完整语义单位。

供应商 Adapter 必须通过同一内部合同套件。增加或更换供应商时，不得修改领域层和页面测试预期。

### 10.2 真实供应商回归

真实调用不进入普通 Pull Request 必跑项。它在专用环境按固定脱敏样例和预算上限运行，用于验证：

- 鉴权、请求格式、超时、模型标识和用量字段；
- 内部 Schema 映射和业务校验；
- 固定质量样例没有明显退化；
- 实际模型来源与费用明细一致。

任何真实调用产生 Token 都必须进入测试专用账本并可对账；禁止通过无限重试追求通过率。

英语候选生成必须额外回归：相邻章节共享同一语义单位且供应商重复候选编号；供应商只返回重点句、漏掉语境句；返回乱序或夹带章外句；可用候选与失败保真候选混合；重复／未知既有知识引用。验收必须证明后台 ID 稳定唯一、已合格句不被重复生成、缺失句仅纠正一次、最终仍按原章顺序完整交付。真实供应商样例至少包含两个重叠章节，不能只验证单章理想输出。

### 10.3 计费尝试

每次真实供应商 attempt 分别验证：

1. 调用前余额预留；
2. 余额不足时供应商调用次数为零；
3. 成功、失败或无效结果均按真实 Token 结算；
4. 自动重试、手动重试和供应商切换产生新调用时形成独立 attempt 和费用；
5. 未产生新供应商调用的幂等重放不产生新预留和费用；
6. 结算后释放多余预留，余额不为负；
7. 并发请求下账本、余额和供应商调用次数一致。

## 11. 并发、幂等与一致性

对支付、账本、审核、operation、消息、最后学习状态、本机固定、章节归档、放弃和回顾提交执行并发测试。

每个用例必须同时断言：

- 最终业务状态；
- 数据库／Room 行数和版本；
- 供应商、支付、消息等外部副作用次数；
- 账本金额和余额；
- 事件和队列消费结果；
- 用户可见的最终页面状态。

至少覆盖重复点击、客户端超时后重试、并发相同幂等键、并发不同幂等键、消息重复投递、乱序投递、Worker 崩溃重启和数据库冲突。不得以“HTTP 返回成功”代替最终一致性验证。

## 12. 故障注入与容错

发布前在隔离环境验证：

- PostgreSQL、Redis、队列、对象存储和单个 API／Worker 实例不可用；
- AI、语音和支付供应商超时、限流、失败与恢复；
- 网络在提交前、提交中、响应返回前和本机落盘前中断；
- 队列重复、乱序、积压、死信和重投；
- 数据库锁冲突、事务回滚和磁盘空间不足；
- Android 录音中切后台、进程被终止、权限变化和低内存；
- 日志／Tracing 平台不可用时核心功能不被阻塞。

降级不得绕过审核、支付验签、余额预留、账号校验或联网限制，不得伪造 AI 成功，也不得把本机资料开放为离线模式。

## 13. 性能、容量与恢复目标

在接近生产配置的 Staging 中验证 `ARCHITECTURE.md` 已确认目标：

| 指标 | 通过标准 |
|---|---|
| 核心 API 可用性 | 月度工程目标 ≥ 99.9% |
| 普通读取 API | P95 服务端耗时 ≤ 300 ms |
| 普通写入 API | P95 服务端耗时 ≤ 500 ms |
| AI／转写任务创建 | P95 ≤ 800 ms 返回可靠 `operationId` |
| 异步任务开始等待 | 正常 P95 ≤ 10 秒；短峰 P95 ≤ 60 秒 |
| 容量基线 | 1,000 活跃会话、持续 100 API RPS |
| 突发流量 | 500 API RPS 持续 5 分钟 |
| 核心 API 非预期错误率 | < 0.1% |
| 云端非账本数据灾难恢复 | RPO ≤ 5 分钟，RTO ≤ 60 分钟 |
| 账本 | 无重复、无丢失、余额不为负 |
| 队列 | 每个已确认任务最终为成功、明确失败、取消或死信之一 |

容量测试同时观察 API、数据库连接池、队列深度、Worker 并发、供应商限额、错误率和费用。不得用无限队列或无限重试掩盖过载。

Android 另外记录：启动、首页可交互、本机数据库迁移、核心页面重组、普通步骤落盘和回顾整章提交耗时。具体设备性能数值在首个可运行纵向切片形成基线后锁定，不在无实测数据时虚构。

## 14. 安全、隐私与无障碍

### 14.1 安全与隐私

发布阻断测试至少包括：

- 跨账号对象 ID 猜测、旧会话访问和越权管理员操作；
- 登录、注销、Token 失效、重放和暴力尝试限制；
- SQL／命令／Prompt 注入、恶意文件、超长文本和异常音频；
- 支付签名、回调来源、金额、订单归属和重复回调；
- 本机 Room、文件和录音的账号隔离与加密；
- 日志、Trace、崩溃报告、分析和测试报告的敏感内容扫描；
- 临时正文到期清理、清理失败重试和审计；
- 依赖漏洞、密钥泄漏和高风险许可证扫描。

### 14.2 无障碍

核心流程必须用屏幕阅读和外接键盘完成。状态不能只靠颜色表达；焦点顺序、控件名称、错误提示、对比度、触控面积、字体放大和减少动态效果必须符合 `DESIGN_SYSTEM.md`。

## 15. 数据库迁移与兼容性

每个 PostgreSQL 和 Room 迁移必须测试：

- 从上一正式版本的真实结构升级；
- 已有数据、约束、索引、账号隔离和金额精度保持；
- 应用旧版与新版在兼容窗口内共同工作；
- expand／migrate／contract 顺序和可恢复方案；
- 大致生产规模下的执行时间、锁影响和失败恢复；
- Room 升级不清空本机学习资料或录音索引；
- 无法安全迁移时阻止启动并给出可定位错误，不静默重建数据库。

每个发布候选至少验证当前 Android 与最低支持服务端合同、上一 Android 与当前服务端合同。破坏性 API 变化必须走新版本或兼容迁移。

## 16. 视觉回归

自动截图固定语义 Token 和组件状态，不按展示图片像素硬编码。至少覆盖：

1. 首页默认与录音中；
2. 日记长文本与放弃确认；
3. AI 场景空推荐和长追问；
4. 重点句达到上限；
5. 英语确认多候选与长句；
6. 普通学习双语上下文和当前任务；
7. 手写画布、两次完成和 `200%` 字体；
8. 多章节统一回顾和退出说明；
9. 词汇本／句式本详情；
10. 支付处理中、失败和退款；
11. 安全拦截、AI 脱敏和人工复核；

## 17. 关键端到端链路

发布候选必须全部通过以下链路：

1. 新用户注册 → 首次设置 → 首页 → 三个入口可见；
2. 日记输入 → 审核 → 固定 → 普通学习 → 完成归档 → 词汇本／句式本更新；
3. AI 场景 → 追问 → 唯一内容结果 → 选择学习项 → 审核 → 学习完成；
4. 快速录音 → 后台录制 → 两分钟截止 → 转写 → 确认 → 学习；
5. 转写失败 → 返回 → 原录音保留 → 重试成功；
6. 内容拦截 → AI 脱敏版 → 用户确认 → 无二次审核进入学习；
7. 内容拦截 → 用户手动提交人工复核 → 消息结果 → 后续操作；
8. 固定前返回修改 → 重新审核／固定；固定后学习中只读；
9. 普通学习中途退出恢复；放弃章节后本章未归档贡献全部清除；
10. 三个普通学习日 → 多章节统一回顾 → 第一章完成 → 第二章退出 → 从第二章章首恢复；
11. 余额不足 → 充值 → 支付回调 → 余额更新 → 原操作按既有状态继续；
12. AI 调用失败／重试／切换供应商 → 每个真实 attempt 正确收费；
13. 断网 → 禁止查看和学习 → 恢复网络 → 鉴权 → 从本机恢复且不重复调用；
14. 退出账号 → 本机资料隔离 → 原账号在原设备登录后恢复；
15. 卸载或清除数据的测试设备 → 登录同账号 → 无法从云端恢复学习资料。

## 19. 缺陷等级与发布准入

| 等级 | 定义示例 | 发布规则 |
|---|---|---|
| P0 | 账号／隐私泄漏、错误扣费、账本不一致、跨账号数据、核心数据损坏、审核绕过、无法启动 | 必须修复，禁止发布 |
| P1 | 核心流程无法完成、录音／学习／回顾主要状态错误、无可接受绕行、频繁崩溃 | 必须修复，禁止发布 |
| P2 | 非核心功能明显错误但有安全绕行，不破坏数据和费用 | 仅经产品与技术共同记录风险、负责人和修复期限后可发布 |
| P3 | 轻微视觉、文案或低频体验问题 | 可进入后续计划，但必须记录 |

合并和发布共同要求：

- 所有必跑测试通过且没有不明原因的偶发失败；
- 没有已知 P0／P1；
- 高风险路径不存在跳过、禁用或只靠人工口头验证的测试；
- 迁移、兼容、并发、幂等和安全门禁通过；
- 测试证据、已知 P2／P3 和监控／回滚方案可追踪；
- 失败测试只能因对应产品功能明确移出范围而删除，不得为通过门禁直接屏蔽。
