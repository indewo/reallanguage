# RealLanguage“连接不可用”排障清单

本文是本项目本机局域网 API 的固定排障顺序。以后出现“连接不可用”时，先运行：

```bash
bash tooling/check-local-api-connection.sh
```

不要先重装、重置账号、清除学习数据或重新生成内容。

## 固定判断顺序

| 顺序 | 已出现或可能出现的原因 | 识别方式 | 解决方案 |
|---|---|---|---|
| 1 | API 登录自启动服务未运行或反复退出 | `launchctl` 无 `com.reallanguage.local-api`，或没有进程监听 3000 | 重新加载/启动该 LaunchAgent；查看标准错误日志，不删除数据库 |
| 2 | 服务只监听本机回环地址 | `127.0.0.1` 健康，但 Wi‑Fi IP 健康失败；端口不是 `*:3000` | API 必须监听 `0.0.0.0:3000` |
| 3 | 健康检查路径写错 | `/health` 返回 404，但 `/api/v1/health` 返回 200 | 固定使用 `/api/v1/health`；404 不等于服务宕机 |
| 4 | Wi-Fi 重新分配了电脑 IP | 旧包内是固定 `192.168.*`，电脑已变为 `10.*` 等 | 新客户端不再写入临时 IP；优先稳定 `.local`，失败后用 DNS-SD `_reallanguage._tcp.` 实时发现当前地址 |
| 5 | 真机不解析 Bonjour `.local` | 电脑和模拟器可用，物理手机提示域名不存在或超时 | 客户端健康检查失败后启动 Android NSD 发现，解析服务广播中的当前地址；不能只凭模拟器认定真机可用 |
| 6 | `.local` 或私网地址误走 VPN/系统代理 | 服务与地址都正常，但应用请求失败；浏览器/代理行为不一致 | 所有 `.local`、`10/8`、`172.16/12`、`192.168/16` 地址使用直连 `Proxy.NO_PROXY` |
| 7 | 手机 VPN、代理、私人 DNS或加速器干扰 | 关闭 Wi‑Fi 后路径变化；系统仍保留代理；浏览器也无法打开健康地址 | 关闭手机 VPN/代理/私人 DNS后重连 Wi‑Fi；客户端私网请求仍强制直连 |
| 8 | Android 局域网/附近设备权限未允许 | Android 13+ 首次启动权限被拒，应用未获得附近设备权限 | 在系统设置中允许 RealLanguage 的“附近设备”；应用对 `.local` 也必须触发权限流程 |
| 9 | Mac 防火墙或“阻止所有传入连接” | 回环健康，LAN 健康失败；防火墙开启 | 允许 RealLanguage/Node 接收入站；不得通过关闭安全功能长期规避 |
| 10 | 手机与电脑不在同一网络或子网 | 手机使用移动数据、访客 Wi‑Fi，或两端地址不属于同一可互访网络 | 两端连接同一普通 Wi‑Fi；关闭移动数据自动切换 |
| 11 | 路由器开启 AP/客户端隔离 | Mac 自测 LAN 地址正常，手机浏览器也打不开 `http://电脑IP:3000/api/v1/health` | 关闭访客网络/客户端隔离，或换个人热点/可互访路由器；应用代码无法绕过路由器隔离 |
| 12 | APK 仍是旧版本或内置占位地址 | 版本号不符，或生成的 `BuildConfig` 是 `https://api.invalid` | 核对版本号与两个 API 地址后再交付；覆盖安装仍需确认实际版本 |
| 13 | 工作区已修复，但登录服务仍运行旧副本 | API 进程工作目录在 `Application Support/RealLanguage/runtime` | 将受影响后端源码安全同步到 runtime，并重启 LaunchAgent，再做 LAN 健康检查 |
| 14 | 端口被别的程序占用 | 3000 端口进程不是 RealLanguage，或健康正文不是 `status=ok, service=api` | 不向错误服务发送账号凭证；先停止冲突程序或调整服务端口 |
| 15 | 账号、响应解析或本地恢复错误被笼统显示为“连接不可用” | 健康检查通过但账号恢复仍失败 | 保留原始错误分类；分别显示网络、认证过期、账号状态、数据恢复错误，不应全部归为网络失败 |
| 16 | Mac 休眠、关机或切换用户 | 自启动服务不再可达 | 唤醒并登录承载 API 的 Mac；本机服务方案天然依赖这台电脑在线 |
| 17 | 无连接参数的普通 Gradle 构建覆盖了已验收 APK | Mac 三路健康均通过，但 `BuildConfig` 回到 `https://api.invalid`/空发现类型 | `apps/android/gradle.properties` 保留 `.local` 主地址和 `_reallanguage._tcp.` 发现类型；每次交付前运行检查器，占位地址或丢失发现配置必须直接判定失败 |
| 18 | 换网络后普通打包仍携带上次的 Wi-Fi 备用地址 | 服务三路健康，但旧版检查器报告 `STALE_OR_MISSING_WIFI_FALLBACK` | code105 起取消静态 IP 备用，改为运行时 DNS-SD 发现；`preDebugBuild` 必须验证发现配置或当前 IP 二者至少有一个有效 |
| 19 | 登录服务运行副本缺少根级 TypeScript 配置 | `launchctl` 中服务消失、3000 未监听，错误日志出现 `File '../../tsconfig.base.json' not found`，检查器报告 `RUNTIME_TSCONFIG_BASE=FAILED` | 从工作区安全同步 `tsconfig.base.json` 到 `Application Support/RealLanguage/runtime/`，重新加载 LaunchAgent；不得删除数据库，随后复查回环、LAN 和 `.local` 健康路径 |
| 20 | 同一天内 Wi-Fi 多次切换，每换一次静态备用 IP 就失效 | `.local` 仍健康，当前 IPv4 从 `10.124.167.36` 变为 `192.168.3.122`，但 APK 内还是 `192.168.1.2` | Mac API 广播 `_reallanguage._tcp.`，Android 请求时解析广播的当前地址；不再为 DHCP 变化重新打包 |

- 这只解决同一可互访局域网中的 DHCP 地址变化。Mac 休眠/关机、跨公网、访客 Wi-Fi 隔离仍不能由局域网发现解决；这些情况的默认长期方案是稳定公网 HTTPS API。

## 当前客户端保护

- 先对候选地址调用 `/api/v1/health`。
- 只有正文明确属于 RealLanguage API，才发送账号请求。
- `.local` 不可解析时通过 DNS-SD 发现当前 IPv4/IPv6，不依赖 APK 内的临时 IP。
- 记住本进程已验证可用的地址；该地址失效后，下次重试重新选择。
- 不因业务错误或读取超时自动重放写请求。

## 真机最小闭环

脚本全部通过后，仍必须在物理手机完成以下一项：用手机浏览器打开脚本输出的
`LAN_HEALTH_URL`。如果浏览器打不开而 Mac 自测能打开，结论是手机到 Mac 的网络
路径被权限、VPN/代理或路由器隔离阻断，不应继续改业务代码或清除用户数据。

## 能否“一次实现以后永远可用”

不能对“Mac 本机 + 任意 Wi‑Fi”作绝对保证。Mac 休眠、IP 变化、物理手机不支持
mDNS/DNS-SD、公共网络客户端隔离都在应用控制范围之外。当前固定主机名、运行时发现与健康选路可以覆盖大多数
家庭/办公局域网变化。

若要求换网络后也无需排障，最终方案应是稳定域名的公网 HTTPS API，或完整实现服务
发现与用户可见的网络诊断；不能继续依赖每次打包写入某个临时 IP。
